# 검수 기준

## 자동 검사

`npm test`는 실제 SDK의 직렬화·파싱과 Redis Lua를 로컬 transport·저장소 더블로 검사합니다. 자동 검사 성공을 유료 API나 이메일 실발송 성공으로 간주하지 않습니다.

주요 대상은 세션 서명, 이력 위·변조, 요청 형식·크기, 공유 한도·중복 처리, 안전 상태 전환, 현재 응급 상황 우선, 질문 거부, 구조화 출력·출력 검수, 중단·시간 초과, 인증·잔액·rate limit 구분, 설문 별도 동의·이메일 고정 수신자·불확실한 접수 재확인입니다.

## 화면 검사

- 360px·390px 휴대폰, 768px 태블릿, 1440px 데스크톱에서 가로 넘침과 입력창 위치 확인
- 감정 선택 후 입력 반영, 선택 표시, 글자 수·전송 상태 일치
- 일기·도움·개인정보·설문 열기와 닫기, 키보드 포커스
- 설문 점수·자유 의견·선택 동의·보관 고지, 새 대화 초기화
- 페이지 이탈 후 뒤로가기에서 이전 입력·대화 초기화
- 연결 실패·시간 초과 시 입력 유지, 만료·상태 오류 시 새 대화 복구
- 한글 조합 중 Enter로 조기 전송되지 않는지 실제 기기 확인

## 배포 후 연결 검사

최종 HTTPS 주소에서 페이지, 보안 헤더, 세션 쿠키, Origin 검증을 확인합니다. 운영자가 비밀 설정을 입력한 뒤 합성 대화 다중 턴·질문 거부·요약·안전 분기를 실제 API로 확인하고, 별도 합성 설문 1건의 수신까지 확인합니다. 검수용 입력에 실명·연락처·실제 상담 내용을 사용하지 않습니다.

실제 기기·계정·메일함 검수가 끝나지 않은 항목은 완료로 표시하지 않습니다. 납품 시점 실행 결과는 함께 제공하는 검수 기록을 확인하세요.
