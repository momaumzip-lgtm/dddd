# 짧은 마음 대화

운영 구성은 `gpt-6-luna` / Responses API / `reasoning.effort: none` / Standard / SDK 자동 재시도 0회입니다.

초기 감정 선택은 대화 턴에 포함하지 않습니다. `lib/emotions.ts`의 명시적 ID 125개(긍정 57, 부정 68)와 범주형 강도를 화면·검색·서버가 공유합니다. 검색 별칭과 공백 없는 표기를 지원하며, 모르는 감정·강도는 미정입니다. 다른 감정을 고르면 강도를 새로 고르고, 정정 발화가 선택보다 우선합니다.

일반적인 첫 자유 입력에는 상황을 짚는 평서문과 구체적인 질문 한 개가 필요합니다. 첫 응답 전용 스키마에서 두 필드를 분리하고, 이 상태에서는 기록과 설문으로 넘어갈 수 없습니다. 듣기·질문 거절, 명시적인 마무리·기록 요청과 안전 안내를 따로 처리합니다. 조언이나 기록만 거절한 경우에는 대화를 이어갈 수 있습니다. 강도는 검증된 구간과 그에 맞는 응답 지침으로 모델에 전달합니다.

좋았던 일을 나누면 그 장면을 짚고 짧은 질문 하나로 이어갑니다. “그냥 좀 서운했어요”처럼 감정만 짧게 말하면 그 차례는 질문 없이 듣습니다. 다음 발화에서 사용자가 이유를 살피거나 기록하고 싶다고 하면 해당 요청을 따릅니다.

현재 UI는 `Accept: application/x-ndjson`로 `/api/chat`에 실제 대화 전체, 최신 메시지 한 개, 감정·강도·선택 버전, 사용자 메시지 ID, 요청 ID와 서명 토큰을 전달합니다. SDK 7.59의 Responses 스트림 파서가 상류 SSE를 읽고, 완결된 JSON 문자열 원소만 문장 단위로 추출합니다. 미완성 JSON 전체를 반복 파싱하지 않습니다. 완결된 문장은 누적 출력 moderation을 거쳐 바로 표시하며 가짜 타자 효과는 없습니다. 완료 모드는 중첩된 판별 스키마에서 한 줄 요약 원소 한 개로 제한합니다. 검수한 초안이 있으면 편집·복사 안내를 붙입니다. 모델이 자발적으로 기록을 제안해도 입력창은 열려 있습니다. 이용자가 정리 버튼을 누르거나 명시적으로 기록·마무리를 요청하면 서버가 완료 상태에 서명합니다. 자연스럽게 제안한 기록 아래에도 설문 링크가 표시됩니다.

일반 경로는 입력 moderation → 생성 LLM 1회 → 문장별 누적 출력 moderation입니다. 입력이 flagged이거나 기존 안전 확인이 해결되지 않았다면 별도 맥락 분류를 유지합니다. 고확신 현재 응급 상황은 고정 안전 안내를 우선합니다. 정상이 아닌 안전 상태에는 일반 완료 카운터를 적용하지 않습니다. 감정 강도만으로 위험을 판정하지 않습니다. 새 스트리밍 경로에는 매 턴 별도 LLM 평가·요약·형식 재생성을 추가하지 않습니다. 기존 JSON 경로는 배포 전 열린 클라이언트와의 호환을 위해 남아 있습니다.

서버가 서명한 진행 정보로 질문 수·일반 턴 수·완료·반영된 메시지 ID를 관리합니다. 대화는 3~5분을 목표로 합니다. 자연 정리는 사용자가 직접 말한 반응의 이유와 새 시각이나 선택이 함께 확인될 때 제안하며 입력창을 유지합니다. 자연 정리와 명시적 마무리 모두 설문을 열 수 있습니다. 모델은 사용자 선택과 확인된 내용에 따라 이어가기, 기록을 포함한 정리, 기록 없는 마침, 안전 안내, 거절 중 하나를 반환합니다. 본문과 별도로 받은 기록 초안은 사용자의 원문에서 근거 구절을 확인하고 출력 검수를 통과한 경우에만 편집기에 표시합니다. 이 검사는 구절의 존재를 확인하며 해석 전체의 정확성을 보증하지 않습니다. 수정된 초안은 현재 화면에서만 유지되고 복사할 수 있습니다. 계속 이야기하기는 완료된 서명 상태에서만 새 구간을 시작하고 대화와 감정은 유지합니다.

`response.completed`와 최종 스키마, 화면에 보낸 본문이 모두 일치해야 성공으로 확정합니다. failed/error/incomplete/refusal 또는 완료 이벤트 없는 종료는 실패입니다. 표시된 일부 문장은 중단 상태로 남고 기존 대화와 입력을 지우지 않습니다. 새 네트워크 요청 ID로 명시적으로 재시도하되 사용자 메시지 ID는 유지합니다. SDK 자동 재시도는 0회, 호출별 12초·AI 작업 전체 30초입니다. 이용 안내 확인 후 세션을 미리 준비합니다. 브라우저는 전송부터 접수 확인까지 35초를 공유하고 첫 답변이 10초 동안 도착하지 않으면 중단 방법을 알립니다.

클라이언트 세대 번호·요청 ID·대화 ID와 선택 버전으로 오래된 응답의 덮어쓰기를 막습니다. 감정 변경은 진행 중 응답을 바꾸지 않고 다음 요청부터 적용됩니다. 마지막 응답 유실에 대비해 완료 답변은 먼저 메타데이터만 준비하고, 브라우저가 서명된 접수증을 확인한 뒤 `/api/chat/ack`로 revision을 확정합니다. ACK 응답이 유실돼도 같은 접수증의 재확인은 멱등이며 LLM을 호출하지 않습니다. 최종 스트림 자체가 유실됐다면 이전 revision으로 명시적으로 다시 생성할 수 있고, 성공한 사용자 턴은 한 번만 반영됩니다. 과거 스트리밍 클라이언트가 ACK를 따로 호출하지 않아도 다음 요청의 서명 토큰으로 수신 확인을 처리합니다. DB에 추가되는 값은 무작위 요청 ID와 revision뿐이며 답변·고민 원문을 저장하지 않습니다. 외부 모델의 정확히 한 번 실행을 약속하는 것은 아니며, 응답 자체가 유실돼 이용자가 다시 생성하면 추가 비용이 생길 수 있습니다.

로그는 요청 ID·모델·시간·토큰·오류 코드만 기록합니다. 실제 입력·답변·감정 선택은 로그나 분석 도구에 보내지 않습니다. 브라우저 performance mark도 요청별 시간만 담습니다. HTTP 접수·서버 시간·첫 문장·브라우저 첫 표시·전체 완료를 구별하며, 소표본을 안정적인 운영 p95로 해석하지 않습니다.

## 대화 품질 검수

운영 지침은 사용자가 구별한 사건의 초점과 감정을 후속 질문·기록까지 유지합니다. 이미 들은 답을 다시 묻지 않고 구체적인 도움에는 먼저 답합니다. 긍정적인 경험과 복합 감정을 하나의 원인으로 단정하지 않습니다. 사용자가 듣기만 원했다가 기록을 요청하면 최신 의사를 적용합니다.

프롬프트 비교에서는 합성 발화, 이전 대화, 모델, 강도, 상태 및 출력 형식을 맞춥니다. 응답의 출처를 가리고 맥락·질문·자연스러움·공감·발견·정정·기록·호흡을 평가한 뒤 출처를 공개합니다. 적용되지 않는 항목은 점수에서 제외합니다. 없는 원인의 단정, 정정 무시, 미확인 해석을 자기 기록에 넣는 경우는 점수와 별도로 실패로 기록합니다.
